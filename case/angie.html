Case 05 · AI prototype · Agentic workflow

Angie — a personal assistant that lives in Telegram

Send Angie a voice note or a message; she summarises email, checks the calendar, and manages tasks and contacts — then replies in the same chat. Built to learn tool-using agents by shipping one.

RoleSolo — design, build, deployment
InterfaceTelegram · voice and text
Stackn8n · OpenAI speech-to-text · Gmail · Calendar · Baserow
HostingRailway (from local Docker)

Product strategy breakdown

01

Context

Personal admin is spread across email, a calendar, a task list and a contact book — four apps to answer one question like "what do I need to do before tomorrow's meeting?"

02

Problem

Switching apps is slow, especially on a phone or on the move. The answer usually needs more than one source.

03

Who it's for

A busy individual (me, first)

Wants answers by voice from a chat app already open all day.

04

Strategic bet

Put the assistant where the user already is. A chat interface with voice beats another app to open.

This is a genuine agent: the model decides which tools to call — email, calendar, tasks, contacts — based on the request, rather than following a fixed path.

05

Scope decisions

In
  • Voice and text input
  • Email summaries, calendar lookup
  • Tasks and contacts in Baserow
Hosting choice
  • Railway over n8n Cloud or a raw VPS — managed HTTPS without running a server
06

How it works

TriggerTelegram message or voice note
TranscribeVoice → text via OpenAI speech-to-text
ReasonAI assistant picks Gmail, Calendar or Baserow tools
ReplyAnswer sent back in Telegram
07

Metrics I'd hold it to

North starRequests answered correctly without opening another app
QualityRight tool chosen · response time
GuardrailsNo action on email or calendar without confirmation · cost per request
08

Risks & trade-offs

Access to personal data. An assistant that reads email needs tight scopes and clear limits on what it can do, not just read.

Infrastructure is product. Telegram webhooks require HTTPS — the local Docker setup failed on exactly that, which drove the move to Railway.

09

Outcome & learning

Building an agent end to end taught me where agent complexity actually lives: tool permissions, deployment and failure handling — not the prompt.
